## Private Network Access (PNA) CORS Fix
- **Issue**: Clicking pruner buttons from browser at LAN IP `192.168.0.191` resulted in `Failed to connect to backend at http://192.168.0.200:8200`.
- **Root Cause**: Chrome/Edge enforce Private Network Access (PNA) preflight checks sending `Access-Control-Request-Private-Network: true`. Starlette's `CORSMiddleware` defaults `allow_private_network=False`, rejecting preflights with `HTTP 400 Bad Request (Disallowed CORS private-network)`.
- **Fix**: Added `allow_private_network=True` to `CORSMiddleware` in `backend/xbot/main.py` and updated `PostPrunerTab.tsx` with explicit status error handling for `rate_limited` responses. Rebuilt dashboard and restarted services. Verified preflights return HTTP 200 OK with `access-control-allow-private-network: true`.
